## 一、需求分析

| # | 需求（用户原话要点） | 现状 | 目标 |
|---|---|---|---|
| 1 | 删除现有的自绘标题栏 | win32 使用 `frame:false` 无框窗口，标题栏完全自绘（`shell.html #titlebar` + 3 个自绘按钮） | 使用操作系统原生标题栏（含原生最小化/最大化/关闭按钮） |
| 2 | 使用原生标题栏，配色和现在统一 | 原生 chrome 未显式设定，跟随系统；窗口无 `backgroundColor` | 原生标题栏深浅配色与应用主题（dark/light）一致，窗口背景不闪白 |
| 3 | 页签重命名功能无用（双击/点击按钮）没有输入标识和输入栏 | 重命名走 `window.prompt()`，Electron 不实现 → 无任何输入框弹出 | 双击/右键/铅笔按钮 → 页签标题原位变为行内输入框（有边框/聚焦环等输入标识），Enter 保存、Esc 取消、失焦保存 |
| 4 | 设置中的开机启动 / 窗口置顶 / 关闭最小化，无用 | ① 开机自启从未调用 `app.setLoginItemSettings`；② 置顶仅保存时应用、show/restore 后可能失效；③ 关闭走 `win.hide()` 隐藏到托盘，窗口从任务栏消失难以恢复 | 三个设置项全部真正生效，行为符合用户预期 |
| 5 | 不能将页签设置为左右两边的垂直页签 | 代码已支持 top/left/right（`window.tabPosition` + `contentBounds` + `shell.css data-position`），但设置页没有「页签位置」选项，只能手改 `config.json` | 设置页提供「外观设置→页签位置」下拉（顶部/左侧/右侧），选择后即时重排生效 |

### 2.4 修改项 3（页签重命名）定位 —— 根因已确认

- `main/shell.js` L22-26：
  ```js
  const rename = () => {
    if (!state.canRename) return;
    const title = window.prompt('页签名称', tab.title);   // ← Electron 不实现 window.prompt
    if (title !== null) window.dshDesktop.renameTab(tab.id, title);
  };
  ```
  Electron 渲染进程**不提供** `window.prompt`（返回 null / 抛错），因此双击/右键/铅笔按钮触发后**没有任何输入框**，`title !== null` 为假，重命名不生效。与用户描述“没有输入标识和输入栏”完全吻合。
- 触发点：`shell.js` L28 双击、L29 右键、L31-36 铅笔按钮（`state.canRename` 时显示）。
- 提交链路：`preload.js` L17 `renameTab` → `main/index.js` L1044-1048 `tab-rename` → `tab-manager.js` L116-125 `rename`（trim/压缩空格/截断 40 字符/置 customTitle）。**提交链路本身正常，仅输入 UI 缺失。**
- 限制：`tab-manager.js` L32 `canRename: tabs.length > 1`、L117 `rename()` 中 `if (tabs.length <= 1) return false` → 单个页签不能重命名（属设计约束，见 4.3 可选放宽）。

## 三、设计

### 修改项 1+2：标题栏原生化 + 配色统一（设计）

1. **原生标题栏**：win32 改回默认边框（`frame:true`/`{}`），移除 `shell.html #titlebar` 自绘标题栏及其按钮与样式；页签栏/启动视图上移（不再预留 40px 标题栏）。
2. **布局联动**：
   - `tab-manager.js TITLEBAR_HEIGHT = 0`（原生标题栏位于 Web 内容区之外）。
   - `shell.css`：`#tabs[data-position=top]{top:0}`；`#startup-view{inset:0 0 0 0}`。
   - 页签栏成为壳内容区最顶部一行（浏览器风格顶部页签，紧随原生标题栏之下）。
3. **配色统一**：
   - `nativeTheme.themeSource = config.theme.mode`（system→system、dark→dark、light→light），启动时设置一次；原生标题栏深浅随应用主题。
   - `BrowserWindow` 增加 `backgroundColor = chromeColorsFor(themeMode()).bg`（dark `#151517` / light `#ffffff`），消除加载白屏；保留 `applyThemeToChrome`。
   - Win11 `backgroundMaterial:'mica'` 可保留（与原生标题栏观感一致），如需彻底一致可移除（任选，见执行步骤 4.2 说明）。
4. **清理**：删除遗留 `inject/titlebar.*`、`theme-observer.js`（可选项，见第六节）。

### 修改项 3：页签行内重命名（设计）

- 触发：双击页签、右键页签、点击铅笔 ✎（触发点不变）。
- 交互流程：
  1. 将 `.tab-title` 原位替换为 `<input class="tab-rename-input">`，预填当前标题。
  2. **输入标识（本次修复的核心）**：
     - 输入框高亮边框（主题主色 `--dsw-primary`）；
     - 聚焦环/外发光（`outline` 半透明主题色）；
     - 光标闪烁（原生 input 自带）；
     - 自动聚焦 + 全选原文（便于直接键入覆盖）。
  3. 行为：Enter 提交；Esc 取消；失焦提交；空值/纯空白 → 还原原标题。
  4. 提交 → `window.dshDesktop.renameTab(id, value)`（走既有 `tab-rename` → `tab-manager.rename` 规范化链路）。
  5. 提交成功后 `tabs-state` 会重建按钮并显示新标题（无需手动还原）；失败/取消时手动还原标题文本。
  6. 互斥：同一时刻至多一个编辑态；编辑中输入框 `click` 不触发页签切换。
- 约束处理：保留 `state.canRename`（`tabs.length > 1`）；若希望单页签也可重命名，见执行步骤 3c 可选放宽。

### 修改项 4：设置三项真正生效（设计）

| 设置项 | 根因 | 设计修复 |
|---|---|---|
| 开机自启 | 从不调用 `app.setLoginItemSettings` | 抽 `applyLoginItem(autoLaunch)`，在 `applyConfigToRuntime`（保存时）与 `app.whenReady` 启动后（首次同步外部修改）调用；`openAsHidden = autoLaunch && closeToTray` |
| 窗口置顶 | 保存时已应用，但 show/restore 循环后可能失效 | 保存时 `setAlwaysOnTop(topMost, 'screen-saver')`；主窗口 `show`/`restore` 事件重断言 |
| 关闭最小化 | 关闭=隐藏到托盘，任务栏消失难恢复 | 关闭 → `win.minimize()`（最小化到任务栏）；设置文案改为“关闭时最小化到任务栏” |

- 设置页（`internal.js renderSettings`）三项开关结构不变；仅文案随 LANG 更新。
- 托盘逻辑不动（已实现且 `updateTrayMenu` 有 `if (!tray) return` 守卫）。

### 修改项 5：页签位置可选（顶部 / 左侧 / 右侧垂直页签）（设计）

- 在设置页新增「外观设置」分组，提供「页签位置」下拉：顶部（默认）/ 左侧 / 右侧。
- 保存时把 `window.tabPosition` 写入配置；`applyConfigToRuntime` 已会触发 `tabManager.layout()+publish()` → 页签栏实时切换方向并重排内容区（**无需重启**）。
- 三种布局：
  - `top`：顶部横排（默认），内容区在页签栏之下；
  - `left`：左侧纵向 184px 垂直页签，内容区右移；
  - `right`：右侧纵向 184px 垂直页签，内容区左移。
- 与修改项 1 联动：原生标题栏（`TITLEBAR_HEIGHT=0`）后，`shell.css` 中 `#tabs[data-position=left/right]` 的 `top:40px` 同样要改为 `top:0`（见步骤 1c）。
- 与修改项 3 联动：垂直页签下行内重命名同样适用（输入框在纵向页签内显示），无需额外改动。

```js
    settled = true;
    const value = input.value.trim();
    if (value && value !== original) {
      window.dshDesktop.renameTab(tab.id, value); // 成功后会收到新 tabs-state 重建按钮
    } else {
      input.replaceWith(titleSpan);
      titleSpan.textContent = original; // 空值/未变化 → 还原
    }
  };
  const cancel = () => {
    if (settled) return;
    settled = true;
    input.replaceWith(titleSpan);
    titleSpan.textContent = original;
  };
  input.addEventListener('keydown', (event) => {
    if (event.key === 'Enter') { event.preventDefault(); commit(); }
    else if (event.key === 'Escape') { event.preventDefault(); cancel(); }
  });
  input.addEventListener('blur', commit);
};

button.addEventListener('dblclick', (event) => { event.preventDefault(); rename(); });
button.addEventListener('contextmenu', (event) => { event.preventDefault(); rename(); });
if (state.canRename) {
  const renameButton = document.createElement('span');
  renameButton.className = 'tab-rename';
  renameButton.textContent = '✎';
  renameButton.title = '重命名';
  renameButton.addEventListener('click', (event) => { event.stopPropagation(); rename(); });
  button.insertBefore(renameButton, button.querySelector('.tab-close'));
}
```

### 6.1 建议一并修复的遗漏

1. **`window.confirm` 同样不生效（`main/internal.js` L96）**：Electron 渲染进程不实现 `confirm`，确认框不弹出、返回值非真 → “关于页 → 更新 DSH”按钮实际不可用。建议改为 IPC + `dialog.showMessageBox`（主进程弹原生确认框），或自绘确认 UI。属隐藏 bug，强烈建议纳入本次执行。
2. **`config.theme.mode` 未映射 nativeTheme**：已列入修改项 2，勿遗漏 `applyNativeTheme` 在启动与主题更新两处调用。
3. **设置页未暴露 `showInTaskbar`**：`applyConfigToRuntime` 会应用 `setSkipTaskbar(!showInTaskbar)`，但 `internal.js renderSettings` 无此开关（用户改不到）。若用户有“任务栏显示”诉求，可在设置页补一个开关（超出 4 项范围，可选）。

### 6.2 优化建议

1. **死代码清理**（见步骤 6）：`settingsHtml`（约 188 行）、遗留 `inject/titlebar.*`、`theme-observer.js`。删减后可显著降低误读与维护成本。

   - 重命名成功可短暂高亮页签（`.tab.active` 闪烁），提供反馈。
3. **置顶级别**：默认 `'screen-saver'` 最稳但激进；若用户反馈“置顶盖过全屏/无法被抢焦点”，改回默认级别并保留 show/restore 重断言即可。

### 6.3 回归风险点
